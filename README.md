# Crypto P&L Dashboard

암호화폐 투자 손익을 기록하고 보는 정적 대시보드.
**입력은 터미널(CLI), 사이트는 뷰어**로 역할이 나뉘어 있고,
데이터는 저장소 안의 JSON 파일이라 GitHub Pages에 그대로 올라간다.

```
data/config.json      계좌 정의 · 기본 환율
data/flows.json       외부 입출금 (원금)
data/snapshots.json   일별 계좌 잔고 · 스테이킹 · 일평균 배당
assets/core.js        계산 로직 — CLI와 웹이 공유한다
tools/cdb.mjs         데이터 입력 CLI (의존성 없음)
index.html            대시보드
```

---

## 계좌 구성

| 계좌 | 성격 |
|---|---|
| **BT** | 법정화폐 입출금 · 원화 ↔ USDT 환전 창구 |
| **OK**, **NA** | 암호화폐 운용 |
| **BC**, **BF** | 암호화폐 운용 + **배당(스테이킹) 상품** |

기본 흐름: 원화를 BT에 입금 → USDT로 환전 → 나머지 4곳을 오가며 운용.

---

## 기록 방식 — 두 가지만 넣으면 된다

엑셀에서 하던 것과 같은 구조다.

1. **원금** — 외부에서 들어오고 나간 돈 (`deposit` / `withdraw`)
2. **잔고** — 그날 각 계좌에 얼마 있었는지 (`snap`)

> **수익 = 총 평가액 − 순 입금액**

계좌 사이 이동(BT→OK 등)은 **기록하지 않는다.** 총액이 변하지 않으므로 손익에
영향이 없고, 일별 잔고 스냅샷이 이미 계좌별 분포를 담고 있다. 거래 하나하나를
적을 필요도 없다 — 하루의 결과 잔고만 있으면 된다.

### 매일 하는 일

```bash
node tools/cdb.mjs snap --bt 20 --ok 7680 --na 6570 --bc 3202 --bf 1067
```

생략한 계좌는 **직전 값을 그대로 이월**한다. 움직인 계좌만 적으면 된다.
환율은 알아서 붙는다.

### 입금했을 때

입출금 경로는 **은행 ↔ BT 원화 한 가지뿐이다.**

```bash
node tools/cdb.mjs deposit 5000000 --note "3월 입금"    # 은행 → BT
node tools/cdb.mjs withdraw 4000000 --note "일부 회수"  # BT → 은행
```

경로가 하나로 정해져 있으므로 **BT의 원화 잔고도 이 명령이 함께 갱신한다.**
따로 `snap` 을 칠 필요가 없다.

```
✔ 2026-08-13  입금 ₩500,000 (은행 → BT)
  ↳ BT 원화 잔고 ₩150,000 → ₩650,000
```

원금과 잔고가 같이 움직이므로 **입출금은 수익을 흔들지 않는다.** 출금은
손실이 아니라 원금 회수이고, 입금으로 없던 수익이 생기지도 않는다.

잔고가 이미 맞는 경우(과거 소급 입력, 기준 잔고 등록)에는 `--no-balance` 를
붙여 원금만 기록한다. 코인 입출금은 기록하지 않는다 — 잔고(`snap`)로만 반영한다.

### 환율 — 자동으로 붙는다

`deposit` · `withdraw` · `snap` 은 `--fx` 를 생략하면 **그 시점의 실시간 시세를
가져와** 스냅샷에 박아 둔다. 과거 날짜(`--date`)면 그날 종가를 가져온다.

```bash
node tools/cdb.mjs fx                    # 지금 시세를 오늘자로 기록
node tools/cdb.mjs fx --date 2026-08-01  # 그날 종가 (Upbit 일봉)
node tools/cdb.mjs fx 1410               # 직접 지정
node tools/cdb.mjs snap --na 71 --no-fx  # 조회 없이 직전 환율 이월 (오프라인)
```

USD/KRW 은행 환율이 아니라 **국내 거래소의 USDT 원화 시세**를 쓴다. 실제
체결가에 가깝고 김프/역프가 반영되기 때문이다. 소스는
`data/config.json` 의 `"fxSource"` — `upbit`(기본) 또는 `bithumb`.
조회에 실패해도 기록은 막히지 않는다. 경고만 띄우고 직전 환율을 이어 쓴다.

사이트가 볼 때마다 시세를 가져오지는 않는다. **기록 시점에 값을 파일에 박아
두는** 방식이라 오프라인에서도 열리고, 볼 때마다 숫자가 달라지지 않는다.

`data/config.json` 의 `"fxMode"` 가 그 값을 어떻게 쓸지 정한다.

| 값 | 동작 |
|---|---|
| `latest` (현재 설정) | **모든 날짜에 최신 환율 하나**를 적용. 일별 환율을 신경 쓸 필요가 없다. 대신 환율이 움직이면 과거 날짜의 원화 환산도 같이 바뀐다 — 어제 본 원화 수익과 오늘 보는 값이 달라진다. |
| `daily` | 그날 환율을 그날에 고정. 과거 원화 수익이 나중 환율로 뒤바뀌지 않는다. |

어느 쪽이든 **USDT 기준 화면은 영향을 받지 않는다.** 환율이 아예 안 끼기
때문이다. 원화 수치가 흔들리는 게 거슬리면 `daily` 로 바꾸면 된다 — 환율은
어차피 자동으로 날짜별로 저장되고 있어서 값만 바꾸면 즉시 적용된다.

### 스테이킹

**스테이킹은 잔고의 일부가 아니라 별도 바구니다.** 거래소에서 스팟 잔고와
스테이킹(Earn) 잔고가 따로 보이는 것과 같다.

> **계좌 총액 = 자유 잔고(`snap`) + 스테이킹(`stake`)**

스테이킹 총액과 일평균 배당은 **직접 유지하는 값이다.** 계산해서 뽑지 않는다.
다시 입력하기 전까지 직전 값이 그대로 이월된다.

```bash
node tools/cdb.mjs stake --벳퓨 16      # BF 스테이킹 총액 (자산에 포함)
node tools/cdb.mjs div   --벳퓨 0.05    # BF 일평균 배당 (USDT)
```

대시보드 스테이킹 섹션에는 계좌마다 두 칸이 선다 — **스테이킹 총액**과
**일평균 배당**. `config.json` 에서 `"yield": true` 인 계좌만 나온다.

## 명령어

| 명령 | 하는 일 |
|---|---|
| `deposit <금액>` / `withdraw <금액>` | 외부 입출금 (원금) |
| `snap --bt N --ok N …` | 일별 계좌 잔고 (USDT) |
| `div --bc N --bf N` | 일평균 배당 (직접 입력) |
| `stake --bc N --bf N` | 스테이킹 총액 |
| `fx [환율]` | 환율 — 인자 없으면 실시간 조회 |
| `show [날짜]` | 하루 요약 — 웹과 동일한 계산 |
| `list [-n 14]` | 최근 스냅샷 표 |
| `flows` | 입출금 내역 |
| `rm snap <날짜>` · `rm flow <id>` | 삭제 |
| `check` | 정합성 검사 (중복·오타·미반영 입금) |
| `serve [--port 8080]` | 로컬 미리보기 |
| `seed <USDT>` | 예정될 보너스 시드 |
| `bonus <USDT>` | 예정된 보너스 |
| `demo` / `reset` | 데모 데이터 생성 / 전체 삭제(백업 후) |

공통 플래그: `--date 2026-08-13`, `--date y`(어제), `--date -3`(3일 전), `--note "..."`

`--bt-krw 50000` 처럼 쓰면 BT에 남은 **원화 잔고**도 기록된다.

### 한글 별칭 — 한영전환 없이

계좌 플래그는 한글로도 받는다.

| 별칭 | 계좌 |
|---|---|
| `--비썸` `--빗썸` | BT |
| `--오케` `--오케이` | OK |
| `--나노` | NA |
| `--비씨` | BC |
| `--벳퓨` | BF |

```bash
node tools/cdb.mjs snap --나노 59 --벳퓨 0 --비썸-원 150000
node tools/cdb.mjs stake --벳퓨 16
```

원화 잔고는 `-원` 또는 `-krw` 를 붙인다 (`--비썸-원` = `--bt-krw`).
별칭은 `data/config.json` 의 계좌별 `"alias"` 배열에서 바꾸거나 늘릴 수 있다.
영문 플래그(`--bt`, `--na` …)도 그대로 쓸 수 있다.

## 보기

```bash
node tools/cdb.mjs serve      # http://localhost:8080
```

`file://`로 열면 브라우저가 JSON fetch를 막으므로 반드시 `serve`를 쓴다.

대시보드 구성:

- **히어로** 현재 총 평가액 + 전일 대비 · 총 수익
- **평가액과 원금** 두 선 사이 면적이 곧 손익 (원금 초과=적, 미달=청)
- **일별 손익** 입출금 효과를 제외한 순수 증감
- **계좌별 잔고 추이** (스택 영역) + **현재 자산 배분**
- **스테이킹** 계좌별 스테이킹 총액 · 일평균 배당 (직접 입력)
- **입출금** 입금/출금 내역 · 총 입금 · 총 출금
- **표로 보기** 모든 값을 숫자로 (차트의 값은 전부 표에서도 읽을 수 있다)

필터는 상단 한 줄 — **기간**(30/90일/전체)과 **통화**(원화/USDT)가 아래 전부를
동시에 바꾼다. URL로도 고정된다: `?currency=USDT&range=30&theme=dark&table=1`

### 원화 기준 vs USDT 기준

- **원화** — 실제 내 손익. 환율 변동 효과가 **포함**된다.
- **USDT** — 순수 코인 운용 성과. 환율 효과가 **빠진다.**

원화로는 이익인데 USDT로는 손실이면, 그 차이는 운용이 아니라 환율이 만든 것이다.

색은 국내 관례를 따라 **상승/수익 = 적색, 하락/손실 = 청색**이며, 색에만 기대지
않도록 부호(`+`/`−`)와 화살표를 항상 함께 표시한다.

## GitHub Pages 배포

```bash
git init && git add -A && git commit -m "crypto dashboard"
git branch -M main
git remote add origin git@github.com:<계정>/<저장소>.git
git push -u origin main
```

저장소 **Settings → Pages → Source: Deploy from a branch → main / (root)**.
빌드 단계가 없다 — 파일 그대로 서비스된다 (`.nojekyll` 포함).

이후에는 기록하고 밀면 끝이다.

```bash
node tools/cdb.mjs snap --ok 7700 --na 6580
git commit -am "$(date +%F)" && git push
```

> **저장소를 private으로 두는 걸 권한다.** public Pages는 잔고가 담긴
> `data/*.json`이 누구에게나 공개된다. private 저장소의 Pages는 GitHub 유료
> 플랜에서만 쓸 수 있으니, 무료 플랜이라면 `serve`로 로컬에서 보는 편이 낫다.

## 데이터 형식

직접 편집해도 된다. CLI는 이 형식을 읽고 쓸 뿐이다.

```jsonc
// data/flows.json
[{ "id": "d20260416-001", "date": "2026-04-16", "type": "deposit",
   "account": "BT", "currency": "KRW", "amount": 20000000,
   "fx": 1372, "note": "초기 입금" }]

// data/snapshots.json
[{ "date": "2026-08-13", "fx": 1397.2,
   "balances": {
     "BT": { "usdt": 40, "krw": 0 },
     "OK": { "usdt": 7681.54 },
     "BC": { "usdt": 3202.19, "staked": 2978.04, "avgDiv": 1.8 }
   }}]
```

`usdt`(자유 잔고)와 `staked`(스테이킹)는 **더해서** 계좌 총액이 된다.
네 값 모두 "현재 상태"라서, 적지 않으면 직전 값이 그대로 이월된다.
편집 후에는 `node tools/cdb.mjs check`.
